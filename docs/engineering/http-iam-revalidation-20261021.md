# 실제 HTTP 경로의 IAM 차단·복구 재검증

2026-10-21 개인 후속 개발에서 합성 자료만 사용해 수행한 AWS 개발자 검증이다. 같은 Uvicorn 프로세스에 loopback TCP HTTP 요청을 보내 IAM 읽기 권한 차단과 복구를 확인했다. 이 검증은 팀 프로젝트와 별개이며, 실제 참가자 접수는 닫혀 있고 전문가 검토는 대기 중이다. 모델 호출은 없었다.

초기 리허설과 앞선 IAM 연결 검사는 별도 실행·별도 경로다. 이 문서는 [초기 결정 기록](aws-rehearsal-decisions.md)이나 [앞선 IAM 연결 재검증](iam-connection-revalidation-20261021.md)의 결과를 소급해 바꾸지 않는다. 실행 범위를 식별 정보 없이 정리한 값은 [비식별 증거 JSON](../evidence/http-iam-revalidation-20261021.json)에 있다.

## 문제와 선택

정책 변경 요청이 성공했다는 사실만으로 앱이 쓰는 기존 연결에서도 권한 차단이 즉시 보인다고 단정할 수 없었다. 새 조회를 대조군으로 삼아 AWS의 거부 여부를 확인하고, 앱의 인증된 실제 HTTP 상태 경로를 같은 프로세스에 반복 호출했다. 인증 요청은 인스턴스 안에서 수행했다. SSM 터널의 readiness 확인은 별도로 다뤘으며 HTTP 검증의 대체 증거로 사용하지 않았다.

기존 연결의 동작을 통제된 조건에서 관찰할 수 있도록, 실행 때만 켜지는 로컬 Unix 소켓 제어를 사용해 기존 SDK 클라이언트를 닫고 필요 시 reconcile을 실행했다. HTTP 관리 경로는 추가하지 않았다. 이 제어는 자격 증명이나 권한 객체를 갈아 끼우는 기능이 아니다.

## 관측 결과

기준 상태의 HTTP 응답은 200이었다. 임시 deny 정책을 적용한 뒤 새 대조 조회에서는 거부가 확인됐지만, 풀을 갱신하기 전 기존 연결을 사용한 앱은 HTTP 200과 준비된 합성 레코드 한 건을 반환했다. 따라서 이 구간에서는 실제 앱 요청의 즉시 차단을 확인하지 못했다.

기존 클라이언트 풀을 명시적으로 갱신한 뒤 앱은 보호된 레코드를 반환하지 않고 503을 응답했다. 권한 복구 단계에서도 새 대조 조회가 허용되는 시점에 기존 앱 요청은 계속 503이었다. 다시 풀을 갱신하고 reconcile을 실행한 다음에야 같은 서버 프로세스가 200을 반환했고, 준비된 합성 레코드의 해시와 개수가 기준 상태와 같았다. 전체 실제 HTTP 상태 순서는 **200 → 503 → 200**이다.

모든 단계에서 참가자 레코드는 0건, 참가자 접수는 닫힘으로 유지됐다. 인증 없는 기준 요청은 401이었다. 임시 정책 제거도 확인했다. 이 관측은 명시적 풀 갱신과 복구 reconcile을 포함한 결과다. IAM 변경의 즉시·자동 반영이나 자동 복구를 보장하지 않으며, AWS 내부 캐시나 전파의 구체적 원인을 밝혀내지 않는다.

## 검증과 정리

검증 과정에서 첫 HTTP probe는 앱에 없는 운영 경로를 가정해 404를 받았다. 실제 `/rehearsal/api/state` 경로로 고친 뒤에는 요약 목록에 전체 레코드 필드가 있다고 가정한 assertion이 실패했다. 두 실패는 IAM deny를 적용하기 전이라 IAM 결과로 세지 않고 별도 기록으로 보존했다. 전체 응답 본문을 기준으로 assertion을 고친 뒤 서버 PID와 레코드 해시를 대조해 준비된 기준 데이터를 재사용했고, 중복 레코드를 만들지 않았다.

시험 전 저장소 기준 커밋은 `51f02da0cf340804626b6730c4d15d6d74a96779`이며, 여기에 이번 전송 제어·probe 관련 소스와 테스트 5개 파일을 추가·수정해 검증했다. 실행 manifest의 다섯 SHA-256은 AWS 검증 당시 값을 그대로 보존했다. 현재 공개본은 네 파일이 바이트 단위로 일치하고, `app/rehearsal_transport_control.py` 한 파일에서만 EOF의 여분 공백 한 줄을 제거했다. 증거 JSON은 원래 AWS 검증 해시와 공개본 해시를 각각 기록한다. 이 한 줄 정규화는 AWS 재검증이 아니다. 소스 계약 테스트 420건과 별도 private probe·정리 감사 계약 테스트 22건을 각각 통과시켰고 Ruff와 셸 구문 검사도 통과했다. 첫 소스 테스트 실행은 환경에 `langgraph`가 없어 일부 실패했으나 의존성을 갖춘 재실행에서 420건이 통과했다. private 테스트는 공개 저장소 테스트 묶음과 별도이며 그 원시 결과는 공개하지 않는다. 소스 193개 파일의 최종 무결성 대조에서는 설명되지 않은 변경이 없었다.

로컬 회귀 검사는 프로젝트 의존성을 설치한 뒤 다음처럼 재현할 수 있다. 두 테스트는 로컬 TCP/Unix 소켓과 가짜 DynamoDB 응답을 사용하며 AWS 계정을 호출하지 않는다. 이 명령은 AWS IAM 시험 결과를 재현하지 않는다.

```bash
RAG_BACKEND=stub AWS_EC2_METADATA_DISABLED=true python -m pytest -q tests/test_rehearsal_transport_control.py tests/test_http_iam_transport.py
RAG_BACKEND=stub AWS_EC2_METADATA_DISABLED=true python -m pytest -q tests/
ruff check .
```

실제 AWS 실행용 harness와 private driver는 공개 저장소에 포함하지 않았다. 따라서 공개된 명령은 로컬 회귀 계약만 재현하며, 권한 정책 변경이나 AWS HTTP 결과를 다시 수행하지 않는다.

2026-10-21 21:55:52 KST에 끝난 해당 실행의 최종 잔여 감사는 34개 점검에서 통과했다(29개 부재 확인, 5개는 전용 버킷 점검에 포함). 잔여 0, 오류 0이었다. 별도 백업 감사도 통과했고 종료 과정에서 S3 객체 버전과 삭제 마커 10개를 제거했다. 이는 이 실행에 생성된 자원 범위만 확인한 결과이며 계정 전체 감사가 아니다.

실행에 승인된 $3 예산은 AWS 청구 강제 상한이 아니며 최종 청구액은 확인하지 않았다. 기록에 남긴 수치는 해당 개발자 검증과 종료 점검을 설명한다. 법률 정확성, 사용자 편익, 실제 전문가 검토, 운영 서비스 가용성 또는 SLA를 증명하지 않는다.
